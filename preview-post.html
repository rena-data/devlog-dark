Python 가상환경(venv) 완벽 가이드 — 프로젝트별 패키지 관리

Python 프로젝트를 진행하다 보면, 프로젝트마다 서로 다른 패키지 버전이 필요한 상황이 자주 생기거든요. 가상환경을 사용하면 프로젝트별로 독립된 Python 환경을 만들 수 있어서 이런 문제를 깔끔하게 해결할 수 있어요.

가상환경이 왜 필요할까?

예를 들어, A 프로젝트에서는 pandas 1.5를 사용하고, B 프로젝트에서는 pandas 2.0이 필요하다면? 전역 환경에 둘 다 설치할 수는 없으니까, 프로젝트마다 독립된 환경이 필요해요.

가상환경은 프로젝트별로 Python 패키지를 격리해서 관리할 수 있는 도구예요. 서로 다른 프로젝트의 의존성이 충돌하는 것을 방지해줘요.

venv로 가상환경 만들기

Python 3.3 이상에는 venv 모듈이 내장되어 있어서 별도 설치 없이 바로 사용할 수 있어요.

1. 가상환경 생성

# 가상환경 생성
python3 -m venv myproject-env

# 디렉토리 구조 확인
ls myproject-env/
# bin/  include/  lib/  pyvenv.cfg

2. 가상환경 활성화

# macOS / Linux
source myproject-env/bin/activate

# Windows
myproject-env\Scripts\activate

# 활성화되면 프롬프트가 변경됩니다
(myproject-env) $

가상환경을 활성화하면 터미널 프롬프트 앞에 (myproject-env)가 표시되면서, 이 환경에서만 패키지가 설치돼요.

3. 패키지 설치 및 확인

# 패키지 설치
pip install pandas numpy matplotlib

# 설치된 패키지 확인
pip list

# requirements.txt 생성
pip freeze > requirements.txt

4. 가상환경 비활성화

deactivate

requirements.txt로 환경 재현하기

다른 개발자가 동일한 환경을 구성하려면 requirements.txt를 사용하면 돼요.

# 다른 환경에서 동일한 패키지 설치
python3 -m venv new-env
source new-env/bin/activate
pip install -r requirements.txt

venv vs conda vs virtualenv

도구장점단점
venvPython 내장, 가벼움Python 버전 관리 불가
condaPython 버전 관리 가능, 데이터 과학 패키지 풍부무겁고 느림
virtualenvPython 2 지원, 빠른 생성별도 설치 필요

마무리

가상환경은 Python 개발의 기본 중의 기본이에요. 프로젝트를 시작할 때 항상 가상환경을 먼저 만드는 습관을 들이면, 나중에 패키지 충돌로 고생할 일이 훨씬 줄어들어요.

다음 글에서는 pyenv와 함께 Python 버전까지 관리하는 방법을 다뤄볼게요.
